iHow to read this airport

A computer moves information around the way an airport moves people. Follow one passenger from the car park to the runway, or click any part of the map.

1Car park

This is the disk.

In the airport

Cars stay in the car park for as long as their owners like, even overnight when the terminal is closed. It holds far more than the terminal, but it is a long walk from the planes.

In the computer

The disk keeps files and programs even when the power is off. It is much bigger than memory but much slower, so a program is first copied from the disk into memory before the processor runs it.

HDD or SSD

An HDD is like a shuttle bus going round a loop: you wait for it to come round to your stop, because the disk is a spinning plate and the data has to turn under the reading head. An SSD is like a moving walkway: nothing goes round, so there is no waiting for it.

Disk type: {{DISK}}

Read from /sys/block/<disk>/queue/rotational: 1 means a spinning disk (HDD), 0 means SSD. On a virtual machine this is whatever the host decides to report.

2Taxi rank

These are the USB devices.

In the airport

Taxis are not part of the airport building. They pull up at the kerb, drop someone off and leave, all day long. The taxi rank itself is always there, even when no taxi is waiting.

In the computer

USB is where things from outside connect: a mouse, a keyboard, a memory stick. They can be plugged in and out while the computer is running. Each device reports a vendor ID and a product ID, like the taxi company and the model of car. The USB controller shows up as a "root hub", the rank itself, even with nothing plugged in.

{{USB_LIST}}

Read from /sys/bus/usb/devices/<device>/idVendor and idProduct. Names come from ids/usb.ids.

3Security

This is the part of a program that cannot be split (Amdahl's law).

In the airport

Every passenger goes through the same security check, one at a time. Opening more runways does not help if everyone is still stuck in the security queue.

In the computer

Most programs have a part that can be shared between cores and a part that has to run on one core, step by step. Amdahl's law says the serial part sets the limit: speedup = 1 ÷ (serial + parallel ÷ cores).

4Departure lounge

This is the memory (RAM).

In the airport

Passengers wait in the lounge right next to the gates, so they can board the moment their plane is ready. The lounge is close but has a limited number of seats, and everyone has to leave when the airport closes.

In the computer

Memory holds the programs and data the processor is using right now. It is fast, but smaller than the disk, and it is emptied when the computer is switched off.

Used and available

Linux counts as "available" the seats that are free plus the seats it can clear quickly, such as copies of files it keeps just in case. We work out used = total − available.

{{SEATS}}

{{MEM_USED}} GiB of {{MEM_TOTAL}} GiB in use ({{MEM_PERCENT}}%). Each seat is 1% of the memory.

Read from /proc/meminfo, lines MemTotal and MemAvailable (in kB).

5Departures board

This is the name lookup in pci.ids and usb.ids.

In the airport

"EI 123" means little to most people until the board says Aer Lingus. The board turns codes into names, and you can read it in gate order or by airline.

In the computer

A device only reports numbers. Intel is vendor 8086 and NVIDIA is 10de. The files pci.ids and usb.ids are the directory that turns those numbers into names. When a number is not in the file, we show the raw number instead.

6Gates and service road

This is the PCI bus and the devices on it.

In the airport

Every gate is reached by the same service road. A gate has an address: which road, which gate, and which door of the jet bridge. The sign at the gate also says what kind of service it offers.

In the computer

The PCI bus connects the processor to the other devices: network card, graphics card, disk controller. Each device has an address made of a bus number (the road), a device number (the gate) and a function number (the door, because one card can do more than one job). A bus has up to 32 devices and each device up to 8 functions. The class code says what the device does: storage, network, display and so on.

7Control tower

This is Linux measuring how busy each core is.

In the airport

The tower keeps a log for every runway: each moment it is busy or empty is counted. The totals only grow, so to know how busy a runway is right now, you read the log, wait, read it again and compare.

In the computer

Linux keeps the same log in /proc/stat: for each core, the ticks (usually 100 per second) spent working and spent idle since the computer started. We read it twice, one second apart, and use the difference: load = busy ÷ (busy + idle).

Runway 0 (core 0) on this machine:

{{TOWER_LOG}}

Busy = user + nice + system + irq + softirq + steal. Idle = idle + iowait. "Steal" is time the host machine gave to another virtual machine.

8Runways

These are the processor cores.

In the airport

Each runway sends off one plane at a time. More runways means more planes leaving at once.

In the computer

Each core runs one task at a time, so 4 cores can run 4 tasks at once. The frequency is how many clock cycles each core runs per second, in millions: 2800 MHz means 2,800 million cycles every second.

Logical and physical cores

With hyper-threading, one physical runway has two queues of planes. When one plane hesitates the next can use the strip, but there is still only one strip, so two logical cores are not as fast as two real ones.
